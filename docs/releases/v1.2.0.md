# Release v1.2.0

`v1.2.0` adds an opt-in, provider-scoped persisted cache for discovered OpenAI-compatible models. It reduces repeated startup discovery requests while preserving explicit OpenCode model configuration as the highest-precedence source.

## New

### Persisted Model Discovery Cache

Enable the cache per provider under `provider.<id>.options.modelsDiscovery.cache`:

```json
{
  "provider": {
    "local-vllm": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "http://127.0.0.1:8000/v1",
        "modelsDiscovery": {
          "enabled": true,
          "cache": {
            "enabled": true,
            "ttlSeconds": 86400
          }
        }
      }
    }
  }
}
```

The cache is disabled by default. When enabled, a successful discovery stores the final filtered and enriched OpenCode model configurations for that provider. A valid cache hit injects those models without requesting the provider's models endpoint, resolving credentials, or repeating metadata enrichment.

Cache entries are provider-specific and are valid only when their provider ID, normalized base URL, models endpoint, schema version, and configured TTL match the current request. Set `ttlSeconds` to `0` to write successful results while forcing a refresh on every later startup.

### Per-Model Cache Overrides

Cache files can contain an optional top-level `overrides` object for durable model customizations, such as model capabilities or OpenCode `variants`. Overrides merge recursively with discovered models, cannot replace a model `id`, and remain separate from plugin-generated cache data.

Runtime precedence is:

```text
cached or live discovered models
  < persisted per-model overrides
  < explicit provider.<id>.models in opencode.json
```

### Safer Cache Storage

Provider cache files are stored in the plugin's XDG data directory, not in OpenCode or Mimocode configuration or authentication stores:

```text
${XDG_DATA_HOME}/opencode-models-discovery/providers/provider-<encoded-provider-id>.json
```

Writes are atomic and use restrictive permissions where supported. Cached data excludes credentials and sensitive connection fields. Invalid, expired, unreadable, or unwritable cache entries fail open: discovery continues normally and successful live discovery remains active for the current session.

## Changed

### LiteLLM Model Metadata Discovery

For providers configured with `modelInfoFormat: "litellm"`, metadata enrichment now defaults to LiteLLM's `/v1/model/info` endpoint. Configure `modelInfoEndpoint` to use a different compatible endpoint.

### Configuration Assistance

`/models-discovery:config` now guides configuration of the persisted cache and management of cache overrides. Cache invalidation and override deletion require confirmation.
