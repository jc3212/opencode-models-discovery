# Release v1.3.1

`v1.3.1` makes OpenAI-compatible provider model discovery more reliable for slow or rate-limited gateways, while preserving the plugin's bounded startup behavior.

## New

### Per-Provider Discovery Timeout

Configure a request timeout for an individual provider under `modelsDiscovery.timeoutMs`:

```json
{
  "provider": {
    "slow-gateway": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://gateway.example.com/v1",
        "modelsDiscovery": {
          "enabled": true,
          "timeoutMs": 10000
        }
      }
    }
  }
}
```

The default is `3000` milliseconds. `timeoutMs` must be a positive, finite number. The configured timeout applies to the provider's `/v1/models` request and to LiteLLM or LM Studio metadata requests when their enrichment format is enabled.

## Changed

### Startup Timeout Protection

The config hook continues to wait for discovery for at least `5000` milliseconds. When a provider has a longer valid `timeoutMs`, the hook automatically waits up to the largest configured provider timeout, so an explicitly configured slow provider is not abandoned before its request can finish.

### Discovery Request Identification

Provider discovery and provider-specific metadata requests now include:

```text
User-Agent: opencode-models-discovery
```

This helps gateways that deprioritize or delay requests without a User-Agent. The value intentionally does not include a package version.
